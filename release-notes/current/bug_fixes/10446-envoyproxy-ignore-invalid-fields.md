An invalid telemetry setting (`clusterStatName`, an access log format or sink, tracing, a metrics sink or Prometheus compression) or an invalid `filterOrder` no longer rejects the whole EnvoyProxy. The invalid field is ignored, the rest of the EnvoyProxy is applied, and the EnvoyProxy status reports a `Warning` condition with reason `InvalidField`. Previously the Gateway was not accepted and its proxy infrastructure was reset to defaults, which could recreate the Envoy Deployment under a different name and drop all traffic. Invalid provider, bootstrap, or `mergeGateways`/`mergeBackends` settings still reject the EnvoyProxy.
