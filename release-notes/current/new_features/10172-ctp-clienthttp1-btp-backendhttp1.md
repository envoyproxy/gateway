Added `BackendTrafficPolicy.spec.http1` (`BackendHTTP1Settings`) for configuring backend HTTP/1 settings such as header-case preservation and trailer support. When both `BackendTrafficPolicy.spec.http1` and the `ClientTrafficPolicy.spec.http1` backend-scoped fields are set, `BackendTrafficPolicy` takes precedence for backend traffic. HTTP/1 settings for non-xRoute backends (ext-auth, ext-proc, OIDC, JWT) are not yet supported via `spec.http1`.

The `EnvoyGateway` runtime flag `ApplyClientTrafficPolicyHTTP1SettingsToClientsOnly` (default: false) can be used to restrict `ClientTrafficPolicy.spec.http1` fields (`enableTrailers`, `preserveHeaderCase`, `http10`) to client connections only, eliminating their effect on backend HTTP/1 protocol settings. When this flag is enabled, use `BackendTrafficPolicy.spec.http1` for backend settings. See the deprecation notice for migration guidance.

When using `mergeBackends`, enabling this flag also allows backend merging across listeners that have a listener-scoped `ClientTrafficPolicy` with `http1` fields set, since those fields no longer affect backend configuration and cannot cause per-listener divergence.
