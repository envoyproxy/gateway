A `SecurityPolicy` whose `authorization` rules reference a JWT provider that is not defined in `jwt.providers` is now rejected with an `Accepted: False` condition, and the routes it targets return a 500 direct response. Previously the policy was accepted but the rule never matched, so a request without a valid JWT was rejected with a 401 and a request with a valid JWT fell through to `authorization.defaultAction`, a 403 when it is `Deny`. Fix the provider name, define the missing provider, or - for a policy with `mergeType` set - define it on the parent policy it merges into.
