An invalid access log sink no longer drops the other access logs, tracing, metrics, or health check event logs of the same EnvoyProxy. The telemetry translator used to abort as soon as a single `backendRefs` entry under `telemetry.accessLog.settings[].sinks[]` failed to resolve, which discarded the whole access log configuration, skipped every telemetry feature processed after it, and marked the Gateway `Accepted: False` even though Envoy kept serving. Each access log setting, sink, and metrics sink is now translated independently, invalid CEL match expressions are dropped individually while the setting keeps its valid ones, and a setting whose expressions are all invalid is skipped instead of being kept with an empty match list (which would log everything). The failures are reported as a `Warning` condition with reason `Warnings` on the EnvoyProxy ancestor that owns the configuration, the Gateway stays `Accepted: True`, and the translation error is logged once per translation with the path of each ignored field.
