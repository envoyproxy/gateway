Widened the buckets of the `watchable_subscribe_duration_seconds` metric to cover 30s, 60s and 120s, so that p95/p99 no longer hide the tail on clusters where a single translation takes longer than 10s, and added `watchable_debounce_pending`, `watchable_debounce_flush_total` and `watchable_debounce_delay_seconds` to observe update debouncing. Note that the pre-existing `watchable_depth` gauge is always 0, because snapshots are delivered over an unbuffered channel; use `watchable_debounce_pending` to see how many updates are being merged.
