Added `http3` to `BackendTrafficPolicy`, enabling HTTP/3 to the backend. The default `Auto` mode uses HTTP/3 only for backends that advertise it through an `alt-svc` response header, racing a QUIC connection against a TCP one so it falls back to HTTP/1.1 or HTTP/2 when QUIC is unavailable, while `Always` sends every request over HTTP/3 without falling back. Because QUIC always runs over TLS, the backend must be configured with TLS through a BackendTLSPolicy or the Backend's `spec.tls`; a policy that enables `http3` for a route with a plaintext backend keeps its other settings, leaves HTTP/3 off for that route, and reports a `Warning` condition. A cluster using HTTP/3 does not apply the EnvoyProxy `backendTLS.alpnProtocols` list, which QUIC cannot offer, and the policy reports a `Warning` saying so. The backend's `alt-svc` header is stripped from the response after Envoy records it, since it names a port on the backend that clients would otherwise try on the Gateway. Routes can combine merged backends using `Auto` and `Always` modes; HTTP/3 discovery remains enabled whenever any backend uses `Auto`.
