Fixed creating or deleting a `SecurityPolicy` whose JWT provider fetches remote JWKS through a `backendRef` updating the listener's `jwt_authn` filter even when an identical provider already existed. The JWKS cluster was named after the policy, so identical providers never deduplicated. It is now named after the backends it points at (kind, namespace, name, and port), their TLS settings, and the traffic settings, so policies that share a JWKS backend share one cluster and one provider, and endpoint changes of that backend do not rename it.
