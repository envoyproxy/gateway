Fixed `ClientTrafficPolicy.spec.clientIPDetection.xForwardedFor.numTrustedHops` configuring Envoy as a non-edge proxy. It was translated to the xff original IP detection extension, which requires `use_remote_address: false`, so Envoy never set `x-envoy-external-address`, left `x-envoy-*` internal headers sent by clients in place, and preserved client-sent `x-request-id` regardless of the configured `requestID` action. The hop count is now set through the connection manager's native `xff_num_trusted_hops` with `use_remote_address: true`: the detected client address is unchanged, and Envoy now also sets `x-envoy-external-address` to it, removes client-sent `x-envoy-*` headers, and applies the `requestID` action. `trustedCIDRs` has no native connection manager equivalent and still uses the extension, so it still does not produce `x-envoy-external-address`; the API and task documentation now state this.
