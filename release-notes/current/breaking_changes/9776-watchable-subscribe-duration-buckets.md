The `watchable_subscribe_duration_seconds` histogram buckets changed from `{0.001, 0.01, 0.1, 1, 5, 10}` to `{0.005, 0.025, 0.1, 0.25, 0.5, 1.0, 2.0, 4.0, 8.0, 15.0, 30.0, 60.0, 120.0}`, matching the spacing already used for the k8s rest client latency metrics. The previous buckets gave almost no discriminating power between 0.1s and 5s (10x and 5x gaps), so p50/p95/p99 for a control plane in that range read as flat regardless of whether it was healthy or steadily degrading. Any dashboard or alert referencing the old `le` bucket boundaries `0.001`, `0.01`, `5`, or `10` needs to be updated, since those boundaries no longer exist (`0.1` and `1` are still present).
