EnvoyExtensionPolicy translation errors that require HTTP 500 now consistently prevent extensions from less specific policies from attaching to the affected routes. Previously, Lua, dynamic module, and Wasm or ExtProc errors requiring HTTP 500 could still allow parent extensions to attach. Response headers, error transformations, and extension side effects provided by parent are no longer applied in these cases. Existing Wasm and ExtProc `failOpen` behavior is preserved.
