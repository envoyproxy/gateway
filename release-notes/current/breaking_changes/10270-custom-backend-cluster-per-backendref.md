Extension servers that use custom backends (`backendResources` in the extension manager) now get one cluster per custom backendRef instead of one cluster per rule. A rule with several backendRefs is routed with `weighted_clusters` and the backendRef weights, where it was previously a single cluster. This also fixes rules that mix a Service or Backend with a custom backend, which ignored the weights and sent all traffic to one side, with the side depending on whether `mergeBackends` was enabled. `PostClusterModifyHook` is called once for each of these clusters, and `PostClusterContext.backend_extension_resources` holds only the custom backend resource for that cluster, plus any resources from the route's `extensionRef` filters. Previously the hook was called once for the rule's single cluster with every custom backend resource in the rule. Clusters for regular Service or Backend backendRefs in the same rule no longer receive custom backend resources, and custom backendRefs with weight 0 are no longer passed to the extension hooks. Extensions that expected several custom backend resources in a single cluster hook call, or that split the merged cluster themselves, need to be updated.
