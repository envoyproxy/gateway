`ClientTrafficPolicy.spec.clientIPDetection.xForwardedFor.numTrustedHops: 0` now means no trusted hops, as Envoy documents: the downstream connection address is the client, and `x-forwarded-proto` is set from the connection. It previously behaved the same as `numTrustedHops: 1`, which trusted the rightmost `X-Forwarded-For` entry sent by an untrusted client. Set `numTrustedHops: 1` to keep the old behavior.
