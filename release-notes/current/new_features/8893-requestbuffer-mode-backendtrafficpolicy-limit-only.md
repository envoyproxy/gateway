Added a `mode` field to `requestBuffer` in `BackendTrafficPolicy`. The default `FullBuffer` keeps the existing behavior of buffering the whole request before forwarding it upstream. The new `LimitOnly` mode only raises the request body buffer limit for the route, so a filter later in the chain can buffer a larger body without the gateway fully buffering the request; unlike `FullBuffer`, it is compatible with protocol upgrades and streaming. Requests whose buffered body exceeds the limit are rejected with HTTP 413 in both modes.
