Added a `clusterSettings` field under `EnvoyGateway.spec.rateLimit` to configure connection-level behavior for the global rate limit service cluster, such as `circuitBreaker.maxRequestsPerConnection` and `timeout.http.maxConnectionDuration`. Supported fields are validated at config-load time, so an invalid value is now rejected at startup instead of only once a Global rate limit policy is used. Route-scoped members (`retry`, `timeout.http.requestTimeout`, `timeout.http.streamIdleTimeout`) have no effect on this cluster; setting them logs a startup warning rather than failing validation.
