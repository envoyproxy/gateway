The gateway-helm chart can render its CRDs as templates of the release, so Helm installs and upgrades them with the chart instead of applying them once from the `crds/` directory: `crds.envoyGateway.managed` for the Envoy Gateway CRDs and `crds.gatewayAPI.managed` for the Gateway API CRDs. Managed CRDs carry `helm.sh/resource-policy: keep` unless `crds.keep` is false, so they stay in place on uninstall and when they leave the release. Helm still applies the `crds/` directory on install, so a release with managed CRDs is installed with `--take-ownership` to adopt CRDs that are already in the cluster, or with `--skip-crds` when every CRD set is managed or installed separately; an existing release switches to managed CRDs with `helm upgrade --take-ownership`.
