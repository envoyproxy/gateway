The SDS secret holding an upstream CA bundle is now named after the Kubernetes object it was read from rather than after the policy reading it. A `BackendTLSPolicy` or `Backend` with a single `caCertificateRefs` entry produces `<kind>/<namespace>/<name>`, for example `configmap/policies/ca-cmap`, in place of the previous `<policy-name>/<policy-namespace>-ca`. Several refs join in declared order, separated by commas. Policies that trust the same object now share one secret instead of each emitting a copy.

EnvoyPatchPolicies and extension servers that match on the old names, or on a cluster's `validationContextSdsSecretConfig`, must be updated. Because several policies can now share one secret, a patch against that secret reaches every policy referencing the same object. Disruption to traffic during upgrade is possible, due to warming of the renamed secrets. Secrets for `WellKnownCACertificates: System` are unaffected.
