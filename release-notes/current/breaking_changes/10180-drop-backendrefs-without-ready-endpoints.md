HTTPRoute and GRPCRoute rules with multiple backendRefs no longer return 503 for the share of traffic routed to backendRefs without ready endpoints when at least one other backendRef in the same rule is available; those backendRefs are excluded from the rule so the remaining backends receive all the traffic per their relative weights. The `BackendsAvailable=False` route condition is still reported, and a 503 is still returned when all backendRefs in the rule have no ready endpoints. As a result, rules mixing invalid backendRefs and backendRefs without ready endpoints now return 500 for the invalid share instead of 503.
