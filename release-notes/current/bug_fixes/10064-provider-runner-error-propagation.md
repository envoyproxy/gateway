Fixed the provider runner swallowing the manager's error, which left the controller process alive with no provider and no health endpoint after it lost the leader lease. `Provider.Start` returns the manager's error, but the goroutine running it only logged that error, so it never reached `RunnerErrors` and the main loop had nothing to exit on. The process then survived until something external killed it — 40 to 45 seconds later via the kubelet liveness probe in the reported case — and with no probe configured it would stay up indefinitely. The failure is now reported through the runner's error notifier, so the process exits, the pod restarts on its own, and the reason is visible. Clean shutdown is unaffected, because `Provider.Start` returns nil once the context is cancelled.
