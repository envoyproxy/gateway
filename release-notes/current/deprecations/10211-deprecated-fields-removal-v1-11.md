The following deprecated fields are now scheduled for removal in v1.11, which is stated in the API reference and in the `DeprecatedField` warning condition set on the resource's status; migrate to their replacements before upgrading: `targetRef` on all policies (use `targetRefs`/`targetSelectors`), `backendRef` on backend clusters such as ext auth, ext proc and OIDC (use `backendRefs`), `host`/`port` on EnvoyProxy tracing, OpenTelemetry metrics and OpenTelemetry access log sinks (use `backendRefs`), `host`/`port` on the EnvoyGateway extension manager service (use `fqdn`/`ip`/`unix`), ClientTrafficPolicy `enableProxyProtocol` (use `proxyProtocol`) and `headers.preserveXRequestID` (use `headers.requestID: PreserveOrGenerate`), BackendTrafficPolicy `compression` (use `compressor`), and the consistent hash `header` field and `Header` type (use `headers` and `Headers`). Deprecation warnings are now also reported for `backendRef` on ext proc, JWT remote JWKS and OIDC providers, for `host`/`backendRef` on EnvoyProxy telemetry sinks, for the consistent hash `header` field and `Header` type, and, in the Envoy Gateway startup log, for `host`/`port` on extension manager and remote infrastructure provider services.
