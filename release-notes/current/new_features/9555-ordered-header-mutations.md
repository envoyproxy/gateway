Added a `mutations` field to `ClientTrafficPolicy`'s `headers.earlyRequestHeaders` and `headers.lateResponseHeaders` filters, an ordered list of header operations applied in exactly the order given. Each entry is one of `write` (a header plus an `action` of `Append`, `Overwrite`, `AddIfAbsent` or `OverwriteIfExists`, and an optional `keepEmptyValue`), `remove`, or `removeOnMatch`. This expresses sequences the existing flat `set`/`add`/`addIfAbsent`/`remove`/`removeOnMatch` fields cannot, such as overwriting a header and then appending to it, or removing a header and then re-adding it.
