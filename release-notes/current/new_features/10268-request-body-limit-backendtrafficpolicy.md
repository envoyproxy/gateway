Added a `requestBodyLimit` field to `BackendTrafficPolicy` that caps the request body size of a route with Envoy's `body_size_limit` filter, without buffering the body. A request whose `Content-Length` exceeds `maxSize` is rejected with HTTP 413 before its body is read; a streamed body is rejected once it passes the limit, with a 413 if the response has not started yet and with a stream reset otherwise. gRPC requests get a trailers-only response with `grpc-status` 2 (UNKNOWN) instead of a 413. Unlike `requestBuffer` with mode `BufferAndLimit`, it costs no memory and keeps HTTP upgrades such as WebSocket enabled.
