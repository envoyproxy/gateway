The SDS secret holding an upstream CA bundle is now named after the Kubernetes object it was read from rather than after the policy reading it. A `BackendTLSPolicy` or `Backend` with a single `caCertificateRefs` entry produces `<kind>/<namespace>/<name>`, for example `configmap/policies/ca-cmap`, in place of the previous `<policy-name>/<policy-namespace>-ca`. A `ClusterTrustBundle` is cluster-scoped, so it has no namespace segment and produces `clustertrustbundle/<name>`. Several refs join in declared order, separated by commas. Names are limited to 128 bytes, shortening the source portion with an underscore followed by a hash when necessary. Policies that trust the same object now share one secret instead of each emitting a copy.

EnvoyPatchPolicies and extension servers that match on the old names, or on a cluster's `validationContextSdsSecretConfig`, must be updated. Disruption to traffic during upgrade is possible, due to warming of the renamed secrets.
