Added an opt-in debounce for the provider reconcile, configurable via the top-level `debounce` field in the EnvoyGateway config. Every watch enqueues the same GatewayClass request, so the workqueue already collapses events that arrive while a reconcile is in flight, but it has no quiet period: when reconciles are fast relative to the event rate, each event costs a full rebuild of the resource tree. When enabled, enqueue requests are held until no new request has arrived for `debounce.after` (default 100ms), or until `debounce.max` (default 10s) if requests keep arriving, so a burst of resource changes costs a single reconcile. Because status is computed during reconcile, enabling this also delays status updates by up to `debounce.max`. Debouncing is disabled by default.
