Fixed WebSocket `Upgrade` requests receiving a misleading `403 (upgrade_failed)` instead of a retryable `503` when the route's backend had no ready endpoints. The no-ready-endpoint route now stays a forwarding route (preserving per-route upgrade configs) and returns `503` via the existing cluster-not-found path, consistent with the partial no-endpoint case. The response status is unchanged for non-upgrade requests; the access log `response_code_details` for the no-endpoint case changes from `direct_response` to `no_healthy_upstream`.
